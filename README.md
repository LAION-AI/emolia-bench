# emolia-bench

Benchmark tooling for emotion-audio annotation quality and CLAP-style model evaluation.

This repository contains:
- Human annotations from 3 raters in `annotations/`
- Original model-selected dataset shards in `dataset/`
- Analysis script to compute agreement and benchmark labels: `analysis.py`
- Benchmark runner for a CLAP-like scoring endpoint (with sham mode): `benchmark.py`
- Optional local sham HTTP server for endpoint testing: `sham_clap_server.py`

## Data Layout

- `annotations/annotations.csv`: item-level user ratings
- `annotations/users.csv`: rater metadata and counts
- `dataset/**/*.json`: sample metadata keyed by clip stem
- `analysis_outputs/`: generated by `analysis.py`
- `benchmark_outputs/`: generated by `benchmark.py`

## Environment

A uv virtual environment is already used in this project.

```bash
uv venv --python 3.13
source .venv/bin/activate
```

Run scripts with:

```bash
./.venv/bin/python <script>.py
```

## 1) Build Benchmark Labels From Human Annotations

Run:

```bash
./.venv/bin/python analysis.py
```

This generates:
- `analysis_outputs/benchmark_labels.csv` (main benchmark table)
- `analysis_outputs/per_task_type_summary.csv`
- `analysis_outputs/per_emotion_summary.csv`
- `analysis_outputs/incomplete_items.csv`
- `analysis_outputs/summary.json`
- `analysis_outputs/report.md`

`benchmark_labels.csv` includes useful columns such as:
- `majority_present` (binary target)
- `benchmark_bucket` (`unanimous_present`, `majority_present`, `majority_absent`, `unanimous_absent`)
- `all_agree_binary`, `all_agree_ordinal`

## 2) Run Model Benchmark (Sham or Remote Endpoint)

### Sham mode (default)

Deterministic fake similarities for pipeline testing:

```bash
./.venv/bin/python benchmark.py
```

### Remote CLAP endpoint mode

```bash
./.venv/bin/python benchmark.py --endpoint http://127.0.0.1:8765/v1/similarity
```

Useful flags:
- `--threshold 0.0`: classify present if similarity >= threshold
- `--limit 500`: quick subset run
- `--output-dir my_outputs`: custom output directory
- `--no-audio-send`: send only stem/text to endpoint

### Expected endpoint contract

`benchmark.py` sends:

```json
{
  "text": "Speech audio in which the speaker expresses or conveys <emotion>.",
  "audio_base64": "<base64 bytes>",
  "audio_filename": "<stem>.json"
}
```

Endpoint should return one of:

```json
{"similarity": 0.42}
```

or

```json
{"score": 0.42}
```

or

```json
{"logit": 0.42}
```

### Benchmark outputs

`benchmark.py` writes:
- `benchmark_outputs/predictions.csv`
- `benchmark_outputs/metrics_by_task_type.csv`
- `benchmark_outputs/metrics_by_benchmark_bucket.csv`
- `benchmark_outputs/summary.json`
- `benchmark_outputs/report.md`

## 3) Optional: Run Local Sham Endpoint Server

```bash
./.venv/bin/python sham_clap_server.py --port 8765
```

Then in another terminal:

```bash
./.venv/bin/python benchmark.py --endpoint http://127.0.0.1:8765/v1/similarity
```

This is useful to test HTTP integration before wiring a real CLAP service.

## Notes

- The benchmark compares model predictions against human `majority_present`.
- For stricter evaluation, filter to `all_agree_binary == True`.
- For confidence-tiered reporting, evaluate separately by `benchmark_bucket`.
